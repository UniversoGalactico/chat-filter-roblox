# Contracts

RemoteGuard.new({Global, Actions, MaxSubjects?, Clock?}) validates and copies configuration. Global and each action Quota use an exact timestamp sliding window (Limit integer 1..256, Window finite 0.001..3600 seconds). Global means across configured actions **for one subject**, not a server-wide quota. Maximum 64 actions, 16 arguments each, 1..4096 tracked subjects (default 256). The maximum possible timestamp-slot count (MaxSubjects multiplied by the sum of all configured quota limits) must not exceed 1,000,000. Clock defaults to os.clock; custom clocks are trusted, synchronous, monotone, seconds in [0, 2^32]. A clock regression fails closed until time catches up. No background work.

Check(subject, action, ...) returns true or false, code, optional detail. Subject must be trusted server-owned identity (normally Player, or scalar test identity). Unknown actions and invalid subjects allocate nothing. Global admission charges before action quota; action admission charges before argument and permission checks. A rejected action can therefore consume global quota; malformed arguments and denied authorization consume both. Requests denied by an already-full global quota do not add timestamps. Known actions must be chosen by server code, not client-provided routing strings. No deduplication or retry immunity; every attempt is charged. Float comparisons use the observed binary64 time, not exact real arithmetic.

Args is a contiguous array of rules. Number supports finite values, optional inclusive Min/Max and Integer boolean. String supports valid UTF-8 and MaxBytes 0..4096 (default 256). Boolean supports true/false. Optional=true permits nil/omission and must be trailing. Extra arguments (including nil) are rejected. Tables, Instances and vectors are deliberately not admitted in v1; validate those separately before using them. No automatic coercion.

Authorize(subject, ...) is optional and must return exactly true, synchronously. It is invoked after shape/quota checks; errors/yields deny, with best-effort thread cancellation. No mutation reentry while callbacks execute. It must be a bounded, side-effect-free server-side predicate. No guarantee against infinite loops, detached tasks or side effects. Authorization is a point-in-time check; gameplay must revalidate after yielding and perform atomic game-specific transactions as needed.

Codes: DESTROYED, BUSY, INVALID_SUBJECT, UNKNOWN_ACTION, INVALID_CLOCK, CLOCK_REGRESSION, CAPACITY, GLOBAL_LIMIT, ACTION_LIMIT, ARG_COUNT, INVALID_ARGUMENT, CALLBACK_ERROR, CALLBACK_YIELDED, UNAUTHORIZED. Third return is seconds to the relevant quota opening (not a guarantee of admission) or invalid argument index. Forget removes subject and resets its budget, only call on trusted lifecycle removal. Count returns tracked subjects. Destroy is idempotent and releases subject/action references, not remote connections. Caller owns connection and cleanup. One serial execution context only. No automatic cross-server quota, network traffic prevention, engine deserialization protection, handler concurrency control or rate-limit logs. No player-supplied identities, prices, privileges, or claims should be trusted.

Memory bounded in number of subjects, actions and timestamp slots; references retained until Forget/Destroy, no idle eviction or capacity claims. Use one shared guard across related remotes. A separate guard has separate quotas. No dependence on GuardUtils; this library adds declarative request policy and layered quotas, rather than replacing general validation helpers.
